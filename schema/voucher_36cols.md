# 金蝶凭证导入模板 — 36 列字段说明

> 列的顺序和字段名必须与导入模板**完全一致**，否则整批导入失败（金蝶按列位解析，不按表头名解析）。
> 本项目 `vouchers.py` 里的 `FIELDS_36` 就是按这个顺序硬编码的。

## 三个容易踩的坑

**1. 幂等键不能用「来源流水号」**

一张凭证至少两行（借 + 贷），两行共享同一个银行流水号。
如果按流水号去重，第二行会被判定为「重复」而整张凭证被丢掉。
本项目改用**凭证号**做幂等键 —— 见 `vouchers.py` 的 `seen_vouchers`。

**2. 借贷平衡必须按凭证判断，不能按行**

单行看永远是「借有贷无」，按行校验会把所有凭证判成不平。
必须先把同一 `凭证号` 的行聚合，比对借方合计与贷方合计。

**3. 税率没确认时不能默认 0**

默认 0 会让凭证顺利过账，但税额全错，等到税务稽核才发现，代价远高于当场阻断。
所以 `rule_tax` 是 fail-closed：税率字段为 `None` 直接进 blocked，附阻断原因。

## 已知不足（真实项目需补）

- **核算项目代码留空**：金蝶要求代码 + 名称成对，只填名称部分版本会报错。真实项目需维护客户/供应商主数据映射表。
- **现金流量项目留空**：银行存款类凭证过账时会被要求补录现金流项目，本项目未做自动指定。
- **未处理红字冲销**：负数金额目前会被 `rule_amount` 拦下，实际业务中红冲凭证是合法场景，需单独放行。
- **未处理多币种**：汇率固定 1，外币业务不适用。
