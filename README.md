# 财务凭证自动化管线

> 把「9 张月结台账手工合并 + 每月 50 张凭证逐张录入」改成一条可复现、可审计、**校验不过就不放行**的管线。
> **纯 Python 标准库，无第三方依赖。**

---

## 这个项目解决什么问题

月度结账的重复劳动有两块：

1. **9 张台账手工合并**——网银对账单 5 张、科目余额表 2 张、往来明细 2 张，分散在不同银行和主体，每次合并都要重新确认口径，一次 10 分钟以上。
2. **每月约 50 张凭证逐张录入**——科目、核算项目、税率、借贷方向全靠人记，错了不容易发现。

但真正的问题不是慢，是**错得看不见**：

- 税率口径还没确认，却按 0 入账了
- 科目编码写错一位，导入照样成功
- 借贷差 0.01，被四舍五入抹平
- 同一笔流水跑了两遍，生成两张凭证

所以这个项目的核心不是「填表」，是 **fail-closed**：任何一条不确定，凭证就进 `blocked`，而不是进导入文件。

## 管线

```
gen_sample.py          合成数据（真实结构 + 故意注入 3 类异常）
      ↓
merge.py               9 张台账合并 + 银行流水透视成客户往来账 + 勾稽自检
      ↓
vouchers.py            36 列映射 + 8 条校验规则 + 放行/阻断分流
      ↓
out/vouchers_ok.csv    可直接导入（UTF-8-BOM，Excel 双击不乱码）
out/vouchers_blocked.csv   带阻断原因，等人工确认
out/voucher_report.md  校验报告
```

跑一遍：

```bash
python gen_sample.py && python merge.py && python vouchers.py
```

实测输出：

```
[merge]   9 张台账合并完成，勾稽：平  差异借方 0.00
[voucher] 放行 74 行 / 阻断 6 行
  - 借贷不平: 2
  - 同凭证连带阻断: 2
  - 税率口径未确认（fail-closed，禁止按 0 入账）: 1
  - 科目不存在: 1
```

那 6 行阻断，正是 `gen_sample.py` 故意注入的 3 类异常——**校验器抓到了它们**。

## 8 条校验规则

| # | 规则 | 为什么必须有 |
|---|---|---|
| R1 | **借贷必须平衡** | 按「整张凭证」判断，不看单行；差 0.01 也算不平 |
| R2 | **科目必须在账套里存在** | 编码错一位，导入照样成功，错在账里 |
| R3 | **税率口径必须已确认** | 未确认一律阻断，**绝不默认 0** —— 这是最危险的一类错 |
| R4 | **金额不能为 0** | 分录行允许单边为 0，但借贷合计必须 > 0 |
| R5 | **日期必须落在本会计期间** | 跨期入账会打乱当期损益 |
| R6 | **摘要不能为空** | 空摘要的凭证审计时无法追溯 |
| R7 | **应收/应付类科目必须带核算项目** | 不带核算项目的往来账等于没记 |
| R8 | **同一凭证号只能生成一次** | 幂等：跑两遍不会多出凭证 |

**连带阻断**：一张凭证里只要有一行没通过，同凭证的其他行也一起阻断——不能只过一半，否则账就断了。

## 三个设计决定

### 1. 借贷平衡按凭证判，不按行判

第一版按行判 `借方 == 贷方`，结果 80 行分录全部被判「借贷不平」——因为真实凭证本来就是一行借、一行贷，单行必然一边是 0。

**教训**：校验的粒度必须和业务对象的粒度一致。凭证是「一张」，不是「一行」。

### 2. 幂等按凭证号判，不按流水号判

同一张凭证的两行共享同一个流水号，按流水号判会把第二行当成重复。

**教训**：幂等键要选那个「业务上唯一」的东西。

### 3. 勾稽只比「银行存款」科目

一开始拿流水合计去比余额表所有科目的本期发生额，永远不平——其他科目的发生额本来就不等于银行流水。

**教训**：勾稽要对得上口径，不是对上总数。

## 36 列字段规范

金蝶凭证导入模板的 36 列，顺序和字段名必须与模板完全一致，否则整批导入失败。
完整定义见 `vouchers.py → FIELDS_36`。

分五组：

| 组 | 字段 |
|---|---|
| 凭证标识 | 凭证字号、凭证号、日期、会计期间、附件数 |
| 分录主体 | 摘要、科目代码、科目名称、币别、汇率 |
| 金额 | 原币金额、借方金额、贷方金额、数量、单价 |
| 辅助核算 | 核算项目类别/代码/名称、部门、职员、客户、供应商、现金流量项目 |
| 业务与税务 | 业务类型、结算方式、结算号、票据号、税率、税额、价税合计 |
| 审计留痕 | 制单人、审核人、过账状态、来源单据、来源流水号、备注 |

## 目录结构

```

├── gen_sample.py     # 合成数据生成（含 3 类异常注入）
├── merge.py          # 9 张台账合并 / 透视 / 勾稽自检
├── vouchers.py       # 36 列映射 + 8 条 fail-closed 校验

├── data/             # 合成数据（运行时生成，不入库）

```

## 说明

- 仓库内**不含任何真实财务数据**。所有公司名、客户名、银行、账号、金额均为虚构。
- 真实项目里数据来自网银导出与金蝶账套；本仓库用 `gen_sample.py` 生成同结构数据，保证可运行。
- 输出为 UTF-8-BOM CSV，Excel 可直接打开；生产环境可换成 openpyxl 直接写 `.xlsx` 并套用导入模板。
- 税率、科目、核算项目等主数据在真实场景中应从账套导出，此处内置通用科目用于演示。
